# Contribuer 

Vous pouvez contribuer de plusieurs façons.

## 1. Aider au développement et à la documentation
Vous aidez à concevoir une fonctionnalité, à résoudre un bug ou à rédiger la documentation.

Pour cela, vous devez **avoir Python installé sur votre ordinateur**. La version utilisée pour développer ce projet est la version **3.14.2**. Si votre version est trop élevée, vous pouvez utiliser un [environnement virtuel](https://pytransit.wordpress.com/2026/04/24/pylearn-mettre-en-place-un-environnement-virtuel/).\

Une fois tout ceci prêt, **effectuez un fork** ou **clonez le code source**.\
Réalisez sur cette version (fork ou code local) votre développement.\
**ATTENTION !** Il faut prendre directement le code source de la branche ``main`` ! Les Releases sont "en retard" par rapport aux fonctionnalités développées !

Si tel est le cas, n'oubliez pas de **vous assigner** à l'[issue](https://github.com/HiAbdounour/SoftVertexGenerator/issues) (le problème) que vous êtes en train de résoudre. Cela évitera que deux personnes perdent du temps à se concentrer sur le même problème !

Une fois votre développement terminé et **relu par vous-même**, vous pouvez émettre une **[pull request](https://github.com/HiAbdounour/SoftVertexGenerator/pulls)**. Des relectures seront sûrement effectuées pour s'assurer que tout se passe bien. Soyez actifs car il est possible que l'on vous demande de revoir des choses ou de modifier des trucs. Lorsque tout est OK, la pull request est acceptée et votre code entre officiellement dans le programme de la prochaine mise à jour !

Voici quelques conseils pour faciliter la compréhension de votre **pull request** :
1. utilisez un titre explicite : évitez les titres simples comme "pull request" ou "résolution de bug"
2. soyez descriptif dans votre pull request : expliquez concisément ce que votre pull request va apporter au projet.
3. ajoutez le label ``need review`` : il signifie que vous attendez que des personnes vérifient la validité de votre pull request
4. si votre pull request répond à un bug ou à une demande précisé dans les [Issues](https://github.com/HiAbdounour/SoftVertexGenerator/issues), n'hésitez pas à la citer (avec un hashtag suivi du numéro de l'issue)

## 2. Ouvrir une issue
Vous aidez à déceler les bugs ou vous souhaitez une nouvelle fonctionnalité.

Grâce aux [issues](https://github.com/HiAbdounour/SoftVertexGenerator/issues), vous aidez l'équipe de développement à repérer les problèmes et donc à se concentrer sur les bonnes choses. Vous pouvez aussi proposer des améliorations ou des fonctionnalités.\
Soyez actifs car il est probable que l'on vous pose des questions pour mieux comprendre votre besoin.

Pour proposer une fonctionnalité ou pour dénoncer un bug, vous avez la possiblité d':
- ouvrir une [issue](https://github.com/HiAbdounour/SoftVertexGenerator/issues)
- ouvrir un ticket sur [le Discord de l'IDFMwiki](https://discord.gg/QcmzQQnDg), salon `boîte-à-idées` (en sélectionnant le tag ``SVG``)

Voici quelques conseils pour faciliter la compréhension de votre **issue** sur GitHub :
1. utilisez un titre explicite : évitez les titres simples comme "bug" ou "nouvelle fonctionnalité"
2. soyez descriptif dans votre issue : expliquez précisément le bug que vous avez rencontré ou la fonctionnalité que vous souhaitez ajouté. Vous avez à votre disposition des modèles que vous pouvez personnaliser (un pour les bugs, un pour les suggestions et un pour les questions).
3. ajoutez quelques labels : vous en avez 20+ , utilisez ce qui correspond à votre issue

## 3. Faire des SVG pour l'IDFMwiki
Vous utilisez pleinement SVG pour l'IDFMwiki.

En utilisant SVG, vous êtes plus à même de découvrir des besoins pour le wiki ou des bugs dans l'outil. Ainsi, vous pouvez dès lors trouver des raisons de contribuer par le 2e moyen *(ouvrir une issue)* ou si vous êtes dev, par le 1er *(aider au développement)*.

Pour rappel, les fichiers XML utilisés pour générer des plans pour l'IDFMwiki doivent être stockés dans le [repo dédié](https://github.com/HiAbdounour/SoftVertexGenerator_IDFM).
